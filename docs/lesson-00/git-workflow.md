# Lesson 00 - Git Workflow

## Purpose

Git is not used only as a backup mechanism in this project.

It is used as an engineering history system that records:

* design decisions,
* experiments,
* improvements,
* problem solving,
* and project evolution.

## Repository Workflow

The standard workflow is:

1. Create or modify files.
2. Review changes.
3. Commit meaningful progress.
4. Push changes to GitHub.
5. Continue development from the updated state.

## Commit Philosophy

Commits should describe engineering changes.

Good examples:

```
Add Lesson 0 environment documentation
Document Git workflow for laboratory projects
Create repository architecture notes
```

Avoid unclear commits:

```
update
changes
fix
test
```

## Commit Size

Commits should be:

* small enough to understand,
* complete enough to represent a meaningful step.

Each commit should tell part of the project story.

## Branch Strategy

The main branch represents the stable history of the laboratory.

Future experiments may use dedicated branches when required.

## Goal

The final repository should demonstrate not only technical results but also the engineering process used to achieve them.
